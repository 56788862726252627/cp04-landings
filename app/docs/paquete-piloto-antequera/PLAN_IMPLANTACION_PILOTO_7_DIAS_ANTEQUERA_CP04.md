# Club Pádel 04 · Plan de implantación piloto en 7 días

## Objetivo

Tener preparado un piloto comercial y operativo de Club Pádel 04 para un primer club real de pádel de Antequera en pocos días, sin activar todavía producción real, pagos reales, reservas reales ni automatizaciones críticas.

## Enfoque

El piloto debe ser rápido, profesional y controlado.

La prioridad no es vender una app terminada al 100% para todos los casos posibles, sino presentar una primera fase sólida, visualmente premium, entendible para el club y preparada para evolucionar.

## Día 1 · Reunión inicial y diagnóstico

### Objetivo

Entender cómo trabaja actualmente el club.

### Acciones

- Presentar brevemente Club Pádel 04.
- Enseñar el PDF comercial premium.
- Mostrar la app visual.
- Preguntar cómo gestionan actualmente reservas, pistas, jugadores, pagos, torneos y comunicación.
- Detectar problemas principales.
- Confirmar si el club quiere una primera fase sencilla o una implantación más avanzada.

### Información a recoger

- Nombre del club.
- Ubicación.
- Número de pistas.
- Horarios.
- Tarifas.
- Responsable principal.
- Personal de recepción.
- Sistema actual de reservas.
- Problemas actuales.
- Prioridades.

### Resultado esperado

El club entiende el valor y acepta avanzar a una propuesta piloto concreta.

## Día 2 · Recogida de datos básicos

### Objetivo

Obtener la información mínima necesaria para adaptar el sistema.

### Acciones

- Rellenar checklist de datos del club.
- Confirmar nombre comercial.
- Confirmar horarios.
- Confirmar pistas.
- Confirmar tipos de usuarios.
- Confirmar reglas básicas de reserva.
- Confirmar qué módulos se enseñarán primero.

### Resultado esperado

Tener datos suficientes para adaptar la demo al club real.

## Día 3 · Adaptación visual y comercial

### Objetivo

Personalizar el sistema para que el club lo vea como una solución propia.

### Acciones

- Ajustar textos visibles.
- Adaptar enfoque comercial al club.
- Revisar PDF comercial.
- Preparar recorrido de demo.
- Ajustar nombres de roles si fuese necesario.
- Preparar mensaje de presentación.

### Resultado esperado

La demo deja de parecer genérica y queda enfocada al club de Antequera.

## Día 4 · Validación interna

### Objetivo

Revisar el sistema antes de enseñarlo a más personas del club.

### Acciones

- Probar pantalla inicial.
- Probar acceso por roles.
- Probar vista jugador.
- Probar reservas visuales.
- Probar torneos.
- Probar ranking.
- Probar staff.
- Probar administrador.
- Probar soporte.
- Revisar PDF.
- Revisar guion de demo.

### Resultado esperado

Demo estable, clara y sin mensajes técnicos visibles para cliente.

## Día 5 · Demo controlada con responsable del club

### Objetivo

Enseñar el sistema de forma comercial y resolver dudas.

### Orden recomendado de demo

1. PDF comercial.
2. Problema actual.
3. Solución propuesta.
4. App visual.
5. Acceso por roles.
6. Vista jugador.
7. Reservas.
8. Torneos.
9. Ranking.
10. Staff / recepción.
11. Administrador.
12. Soporte técnico.
13. Fases futuras.
14. Precio.
15. Siguiente paso.

### Resultado esperado

El responsable entiende qué compra, qué incluye, qué no incluye y cómo sería la implantación.

## Día 6 · Ajustes posteriores a la demo

### Objetivo

Corregir dudas, adaptar detalles y preparar cierre.

### Acciones

- Anotar objeciones.
- Ajustar propuesta si es necesario.
- Confirmar si el pack recomendado encaja.
- Revisar precio.
- Revisar mantenimiento mensual.
- Confirmar alcance final.
- Preparar documento de siguientes pasos.

### Resultado esperado

Propuesta lista para decisión.

## Día 7 · Cierre del piloto

### Objetivo

Concretar si el club avanza con el Pack Fundador.

### Acciones

- Confirmar decisión.
- Confirmar pack elegido.
- Confirmar calendario de implantación.
- Confirmar datos pendientes.
- Confirmar forma de pago.
- Confirmar responsable de comunicación.
- Confirmar si se activa dominio, pagos, WhatsApp o automatizaciones en fases futuras.

### Resultado esperado

Club listo para iniciar implantación real controlada.

## Entregables del piloto

- App visual preparada.
- PDF comercial premium.
- Guion de demo.
- Checklist de datos.
- Alcance del piloto.
- Condiciones Pack Fundador.
- Plan de implantación.
- Checklist de envío comercial.
- Documentación de auditorías.
- Checkpoints de seguridad.

## Reglas de seguridad

Durante el piloto no se activan:

- Pagos reales.
- Reservas reales.
- Cancelaciones reales.
- WhatsApp Business real.
- Webhooks reales.
- Escrituras reales en Airtable.
- Producción comercial.
- DNS.
- Dominio definitivo.

## Criterio para pasar a producción real

Solo pasar a producción real cuando:

- El club apruebe el alcance.
- El club acepte precio y mantenimiento.
- Los datos estén revisados.
- La demo esté validada.
- Se haya hecho una prueba controlada.
- Se confirme qué funciones serán reales.
- Se definan responsables.
- Se documenten límites y condiciones.
