# GUIÓN DEMO COMERCIAL · Club Pádel 04

## Objetivo

Tener un guion claro para enseñar Club Pádel 04 a un club deportivo o club de pádel real sin improvisar, sin prometer funciones no terminadas y enfocando la demo en valor comercial.

## Mensaje inicial

Lo que quiero enseñarte no es solo una web. Es una base de sistema digital para un club de pádel que permite centralizar reservas, jugadores, roles, administración, automatizaciones y soporte en una app personalizada.”

## 1. Contexto del problema

Explicar:

- Muchos clubes gestionan reservas por WhatsApp, llamadas o herramientas poco adaptadas.
- Se pierde tiempo respondiendo mensajes repetitivos.
- Es difícil ver ocupación, jugadores activos, cancelaciones y seguimiento.
- La experiencia del jugador puede mejorar mucho con una app clara.

Pregunta inicial:

Cómo gestionáis ahora las reservas y qué parte os quita más tiempo?”

## 2. Pantalla inicial / acceso

Mostrar o explicar:

- app personalizada
- identidad visual del club
- acceso por roles
- modo demo
- entorno protegido

Mensaje:

La idea es que cada tipo de usuario vea solo lo que necesita.”

## 3. Roles

Explicar roles principales:

- Usuario / jugador
- Empleado / recepción
- Administrador / gerente
- Soporte técnico

Mensaje:

El valor está en separar permisos y responsabilidades. No todo el mundo debe ver lo mismo.”

## 4. Reservas

Mostrar o explicar:

- crear reserva
- elegir fecha
- elegir hora
- elegir pista
- ver disponibilidad
- cancelar o reprogramar, si está preparado
- confirmación

Mensaje:

La reserva es el corazón del sistema. Todo lo demás se conecta alrededor: avisos, ocupación, historial y administración.”

## 5. Perfil y ajustes

Mostrar:

- perfil del usuario
- datos básicos
- idioma si procede
- seguridad visual
- ajustes generales

Mensaje:

Esto ayuda a que cada usuario tenga su espacio y no dependa todo de recepción.”

## 6. Administración

Mostrar o explicar:

- reservas del día
- usuarios
- métricas
- ocupación
- gestión interna
- soporte

Mensaje:

El administrador necesita ver el estado del club, no solo reservas sueltas.”

## 7. Automatizaciones

Explicar sin prometer lo que no esté terminado:

- altas de jugadores
- confirmaciones
- cancelaciones
- alertas internas
- recordatorios
- futuras integraciones

Mensaje:

Las automatizaciones reducen trabajo repetitivo. Primero se validan las más útiles y luego se amplía.”

## 8. Límites de la demo

Decir claramente:

- “Esta demo no ejecuta pagos reales.”
- “No cancela reservas reales.”
- “No envía WhatsApp real todavía si no está configurado.”
- “La demo sirve para validar flujo, diseño y utilidad.”
- “Las integraciones finales se activan por fases.”

## 9. Cierre

Mensaje final:

El objetivo es crear un sistema que ahorre tiempo al club, mejore la experiencia de los jugadores y permita crecer con automatizaciones, sin depender de parches manuales.”

## Preguntas finales

- ¿Qué parte te parece más útil?
- ¿Qué módulo usaríais primero?
- ¿Qué problema os gustaría resolver antes?
- ¿Cuántas reservas gestionáis por semana?
- ¿Qué herramienta usáis actualmente?
- ¿Qué presupuesto mensual tendría sentido si el sistema os ahorra tiempo?
