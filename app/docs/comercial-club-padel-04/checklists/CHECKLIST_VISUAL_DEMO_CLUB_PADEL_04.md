# CHECKLIST VISUAL · Demo Club Pádel 04

## Antes de enseñar la demo

- [ ] La app carga correctamente.
- [ ] No aparece pantalla negra.
- [ ] No aparecen errores visibles en consola.
- [ ] No aparecen credenciales.
- [ ] No aparecen tokens.
- [ ] No aparecen datos privados reales.
- [ ] El diseño principal se ve estable.
- [ ] El sidebar se ve correctamente.
- [ ] Los botones principales son legibles.
- [ ] El módulo de perfil se ve correcto.
- [ ] El módulo de idioma no rompe la pantalla.
- [ ] El fondo visual no tapa textos importantes.
- [ ] La demo se puede explicar sin depender de funciones incompletas.

## Qué enseñar

- [ ] Inicio.
- [ ] Roles.
- [ ] Reservas.
- [ ] Perfil.
- [ ] Panel administrador.
- [ ] Automatizaciones conceptuales.
- [ ] Propuesta de valor.

## Qué no enseñar si no está terminado

- [ ] Pagos reales.
- [ ] WhatsApp real.
- [ ] Funciones con errores visuales.
- [ ] Módulos incompletos.
- [ ] Datos técnicos internos.
- [ ] Carpetas del proyecto.
- [ ] Terminal.
- [ ] Make/Airtable con credenciales.

## Frases seguras

- “Esto está en modo demo.”
- “La integración final se activa por fases.”
- “Primero validamos el flujo principal.”
- “No se realizan pagos reales en esta demo.”
- “No se modifican reservas reales.”
- “El objetivo es ver si esto resuelve vuestro problema.”

## Señales de demo lista

- [ ] La app se entiende en menos de 2 minutos.
- [ ] Se puede explicar qué problema resuelve.
- [ ] Se puede mostrar el flujo de reserva.
- [ ] Se puede explicar el panel admin.
- [ ] Se puede explicar mantenimiento mensual.
- [ ] Se puede cerrar con una pregunta comercial.
