# MATRIZ DE CAMBIOS · Réplica Club Pádel Demo

## Objetivo

Diferenciar qué se reutiliza, qué se adapta y qué se crea nuevo al replicar Club Pádel 04 para otro club de pádel.

---

## 1. Reutilizar sin cambios importantes

| Elemento | Acción |
|---|---|
| Estructura base de app | Reutilizar |
| Roles principales | Reutilizar |
| Dashboard | Reutilizar y adaptar textos |
| Reservas | Reutilizar |
| Perfil | Reutilizar |
| Login | Reutilizar |
| Recuperación contraseña | Reutilizar |
| Modo seguro | Reutilizar |
| Documentación de auditorías | Referenciar |
| Checklists | Reutilizar |
| Paquetes comerciales | Adaptar mínimamente |

---

## 2. Adaptar por cliente

| Elemento | Acción |
|---|---|
| Nombre Club Pádel 04 | Cambiar por nombre del cliente |
| Logo | Sustituir |
| Fondo Torcal/Antequera | Sustituir o adaptar |
| Colores | Adaptar si procede |
| Ciudad | Cambiar |
| Textos de bienvenida | Adaptar |
| Número de pistas | Configurar |
| Tarifas | Configurar |
| Horarios | Configurar |
| Emails | Personalizar |
| Datos de contacto | Personalizar |
| Propuesta comercial | Personalizar |

---

## 3. Crear solo si falta

| Elemento | Crear solo si... |
|---|---|
| Nuevo módulo | El cliente lo necesita realmente |
| Nueva automatización | No existe flujo equivalente |
| Nueva tabla Airtable | No encaja en estructura actual |
| Nuevo agente IA | Hay caso de uso específico |
| Nuevo documento | No existe plantilla reutilizable |
| Nueva carpeta | No hay ubicación adecuada existente |

---

## 4. No hacer todavía

No hacer en esta fase:

- no duplicar App.jsx
- no crear una segunda app completa
- no tocar CSS
- no cambiar rutas
- no modificar Make real
- no tocar Airtable real
- no crear pagos reales
- no prometer WhatsApp si no está configurado
- no borrar backups

---

## 5. Conclusión

La primera réplica de otro club de pádel debería ser de bajo riesgo porque reutiliza casi todo el núcleo de Club Pádel 04.

El trabajo principal será parametrizar marca, textos, recursos y automatizaciones.
