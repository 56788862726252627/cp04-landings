# Club Pádel 04 · Límites técnicos del piloto controlado

## Objetivo

Definir qué puede probarse y qué no debe activarse todavía durante un piloto técnico controlado.

## Permitido durante el piloto

- Mostrar la app visual.
- Navegar por las pantallas principales.
- Enseñar roles de jugador, staff, administrador y soporte.
- Simular reservas con datos ficticios.
- Explicar cómo funcionarían las automatizaciones.
- Enseñar PDF comercial.
- Enseñar paquete maestro.
- Revisar propuesta y condiciones.
- Recoger datos básicos del club.
- Preparar un entorno futuro de pruebas.

## No permitido todavía

- Cobrar pagos reales.
- Crear reservas reales.
- Cancelar reservas reales.
- Enviar correos reales a clientes del club.
- Enviar WhatsApp reales desde una cuenta del club.
- Conectar Airtable real del cliente.
- Activar webhooks reales de producción.
- Conectar dominio definitivo.
- Modificar DNS.
- Publicar como producción comercial.
- Prometer disponibilidad 24/7.
- Prometer integración ilimitada sin presupuesto cerrado.

## Datos permitidos

Durante esta fase solo deben usarse:

- Datos ficticios.
- Datos de ejemplo.
- Información pública del club.
- Datos básicos facilitados voluntariamente para preparar propuesta.

## Datos no permitidos sin autorización formal

- Datos reales de jugadores.
- Teléfonos reales de socios.
- Correos reales de clientes.
- Historial real de reservas.
- Datos bancarios.
- Datos de pagos.
- Credenciales del club.
- Accesos internos privados.

## Requisito antes de usar datos reales

Antes de usar datos reales debe existir:

1. Autorización expresa.
2. Alcance documentado.
3. Responsable del club definido.
4. Entorno separado de pruebas.
5. Copia de seguridad.
6. Política clara de protección de datos.
7. Confirmación de que no se harán acciones irreversibles.
